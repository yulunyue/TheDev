---

你正在执行 `/refactor` 命令。参数说明：

1. `$1` — 重构目标，可选。可以是文件路径、函数名、类名、模块名，或 `unstaged`（当前未提交的变更文件）
2. `$2` — 重构类型，可选。值为 `structure`（结构）、`naming`（命名）、`performance`（性能）、`readability`（可读性）

执行流程：

1. **分析目标**：
   - 如 `$1` 为 `unstaged`，分析 `git status --porcelain` 中所有未提交的文件
   - 如提供其他 `$1`，定位目标代码（文件、函数、类、模块）
   - 如未提供 `$1`，分析当前 git diff 或最近变更的文件

2. **识别问题**：
   - 重复代码
   - 过长函数/类
   - 命名不清晰
   - 复杂条件逻辑
   - 性能瓶颈
   - 违反项目规范

3. **生成重构方案**：
   - 列出具体改动点
   - 说明每个改动的理由
   - 评估风险和影响范围

4. **执行重构**（需用户确认后执行）：
   - 小步修改，每次只改一个问题
   - 保持功能不变
   - 遵循项目代码风格（Black 格式化，行长度 88）

5. **验证**：
   - 运行 `python -m pytest tests/` 确保测试通过
   - 运行 `black .` 格式化代码

**遵循规则**：
- **一个文件一个类**：如发现文件包含多个类，拆分为独立文件
- 重构不改变功能行为
- 每次重构聚焦单一目标
- 优先处理高频使用的代码
- 变更记录到同目录同名的 `.md` 文件
- 涉及 API 变更时需更新相关文档
