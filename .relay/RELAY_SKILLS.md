# TheDev 项目 Relay 工作流指南

## 角色定位

TheDev 是一个**个人实验项目**，采用Python + Tornado架构，集成算法工具、用户管理、API服务等模块。项目特点是：简洁至上、实用主义、持续迭代、多语言探索。

## 工作流程概览

```
用户请求 → 任务识别 → 代理委派 → 执行 → 结果交付
```

## 项目特定指导原则

### 开发原则
1. **简洁至上**: 避免过度工程化，选择合适技术
2. **实用主义**: JSON文件存储满足基本需求
3. **持续迭代**: 永远在开发中，无固定release版本
4. **多语言探索**: 集成Python、Rust、C++等
5. **算法实践**: 包含竞赛题目和游戏算法

### 技术约束
- **异步优先**: 所有I/O操作必须使用异步模式
- **模块化**: 新功能必须设计为独立模块
- **配置驱动**: 通过配置文件控制行为
- **测试覆盖**: 新代码必须有对应测试
- **文档先行**: 重要功能需要文档说明

### 文件组织规范
```
TheDev/
├── app/                    # 应用模块
│   ├── tool/              # 核心功能 (api.py, user.py, algo.py等)
│   ├── xx/                # 扩展模块
│   └── yly/               # 专用模块
├── common/                # 通用库
├── config/                # 配置文件
├── data/                  # 数据存储
├── doc/                   # 文档
├── rust/                  # Rust项目
├── cpp/                   # C++项目
└── tool/                  # 开发工具
```

## 质量保证

### 代码质量标准
- **测试覆盖率**: >80%
- **代码规范**: 严格遵循PEP 8
- **异步模式**: 所有I/O操作必须异步
- **错误处理**: 完整的异常处理机制
- **日志记录**: 关键操作必须有日志

### 文档质量标准
- **API文档**: 所有公共接口必须有文档
- **架构文档**: 核心模块需要架构说明
- **部署文档**: 环境配置和部署步骤
- **用户文档**: 功能使用说明

### 性能标准
- **API响应**: <100ms (普通接口)
- **并发支持**: 支持100+并发连接
- **内存使用**: <500MB (基础运行)
- **启动时间**: <10s

## 工作流最佳实践

### 1. 任务分解
复杂任务应该分解为多个子任务，每个子任务由合适的代理完成。

### 2. 并行执行
独立的任务可以并行执行，提高效率。

### 3. 结果验证
每个代理完成任务后，需要验证结果是否符合预期。

### 4. 持续改进
根据项目发展，不断更新和完善代理工作流程。

### 5. 知识积累
重要的技术决策和解决方案需要记录到项目知识库中。

## 注意事项

1. **项目定位**: 这是一个个人实验项目，没有严格的版本控制和发布流程
2. **技术债务**: 部分代码可能存在技术债务，需要逐步重构
3. **扩展性**: 设计时要考虑未来的扩展需求
4. **兼容性**: 新功能要考虑与现有模块的兼容性
5. **安全性**: 特别是用户认证和数据安全方面需要重点关注
